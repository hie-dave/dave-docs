Plain text input files

Use named file blocks in your instruction file to configure plaintext input files. Currently, these are only supported by soil inputs, but other existing plaintext inputs will be gradually migrated to this form. The plain text file reader supports static (time-invariant), annual and daily tables, but each model component decides which of those formats it can use. Soil inputs are static. Other inputs, including CO₂, grazing and land cover, still use their existing settings and readers; adding a file block does not switch those readers.

A first example

Given this file, soil.csv:

lon,lat,sand,clay,orgC,pH
150.75,-33.5,0.4,0.2,0.05,6.5

configure it with:

file "soildata" (
    path "soil.csv"
    column "orgc" (source "orgC")
    column "ph" (source "pH")
    max_distance 0.1
)
slope 0
depth_soil 1500

This supplies soil properties for locations within 0.1 degrees of the table coordinate, with a fixed slope of zero degrees and soil depth of 1500 mm. The reader detects the comma separator and header. Column mappings connect the model's names, orgc and ph, to the file's names, orgC and pH.

path is the only mandatory option inside a file block. Relative paths start at the simulation's working directory, including when the block is in an imported instruction file. Absolute paths are also accepted. A later block with the same name replaces the whole earlier block.

Parsing options

Option values and file block names are case sensitive.

Option Default Meaning and accepted values
path Required Path to the data file.
delimiter "infer" Detect the separator, or choose ",", ";", "\|", " " or "\t".
sample_rows 64 Number of nonblank rows inspected when detecting the delimiter, including the header. 0 examines all rows; accepted range is 0–1000000000. All data rows are validated regardless of this setting.
header "infer" "present" treats the first nonblank row as column names; "absent" treats it as data. Inference recognises an all-text first row as a header.
domain "infer" "local" requires longitude and latitude; "global" applies one table to every gridcell. Inference uses coordinate headers. Specify this for headerless files.
timestep "infer" "none" for static values, "annual" for yearly values, "daily" for daily values. Inference uses year/day headers. Soil files must be static.
calendar "noleap" Daily files: "noleap" has 365 days every year; "gregorian" includes leap days. This does not change the model's simulation calendar.
quote Double quote A single quote character, or "" to disable quoting. Write quote '"' to explicitly select double quotes.
trim_whitespace 1 Strip surrounding spaces and tabs from unquoted fields; 0 preserves them. Quoted content is preserved.
max_distance 0 Maximum distance to a matching file coordinate, in degrees; accepted range 0–360. Zero requires exact coordinates.
column "name" (source "source_name") No mappings Associate a supported model column with a source data column. Repeat for each mapping.

Instruction files do not interpret backslash escapes: write the literal two-character string "\t" to select tabs. With delimiter " ", runs of spaces and tabs count as one separator. Other separators preserve empty fields, so a missing CSV or TSV value produces an error instead of shifting later columns.

Delimiter detection samples comma, tab, whitespace, semicolon and pipe separators. If a file is ambiguous, set delimiter explicitly. Increasing sample_rows can help when the beginning is not representative of the entire file.

Set header explicitly if a row of text is actually data, or your column names are numeric..

Columns and table layouts

Structural headers are case insensitive:

Role Recognised names
Longitude lon, longitude
Latitude lat, latitude
Calendar year year
Day of year day, doy

Both coordinates must be present together. Day requires year. Structural columns may appear anywhere in a headed file. Use longitude in −180..180 and latitude in −90..90. All other headers name data columns. Duplicate headers, including names differing only in case, are rejected.

Data column names and mappings match exactly, including case. Only columns supported by the consuming component can be mapped. Each source may be mapped once; mappings cannot create duplicate exposed names. Coordinate/time columns cannot be mapped: rename those headers to a recognised structural name instead. Extra columns are accepted, but still parsed and validated.

For headerless tables, set header "absent" and specify domain and timestep. Soil sets the static timestep automatically. Column order for such files is:

Domain Timestep Order
global none Data columns
local none Longitude, latitude, data columns
global annual Year, data columns
local annual Longitude, latitude, year, data columns
global daily Year, day, data columns
local daily Longitude, latitude, year, day, data columns

Headerless data columns are numbered "0", "1", etc., excluding coordinates and dates. For example, a headerless depth map with rows 150.75 -33.5 1.5 uses:

file "soildepth" (
    path "depth.dat"
    domain "local"
    timestep "none"
    header "absent"
    column "depth" (source "0")
)

A reader with both shape settings left as infer can also recognise one headerless row as global static data. Downstream components may impose a shape, so explicit settings are preferable for headerless input.

A global static file has one data row. For example, omit coordinates from the first example to apply its properties everywhere. Legacy headed global files with a static dummy column, such as static sand clay ..., are accepted; the dummy value must be numeric. Headerless files have no implicit dummy.

Numbers, text and quoting

Numbers use a period as the decimal point, independent of the computer's locale. Signed values and scientific notation, such as -1.5e-3, are accepted. Thousands separators, partially numeric values, hexadecimal numbers, infinity, NaN, overflow and underflow to zero are rejected. Booleans use true/false, case insensitive. The component chooses required column types; there is no instruction-file type setting. Other columns have their types inferred from the complete file, and may contain integers, real numbers, booleans or text.

Missing numeric values are not supported: empty fields, NA, NaN, Inf, Infinity and null cause errors. Mixed text/numeric columns require the component to declare them as text. Quoting a number or missing-value marker does not force a numeric column to become text. An empty quoted string is valid only for a text column.

Quotes allow separators within a field. Double the quote character to include it, for example "a ""quoted"" label". Quoted fields must stay on one physical line. Unclosed quotes, quotes within unquoted fields, and text after a closing quote are errors. Blank lines are ignored. Comment lines and inline comments are not supported in data files; ! comments belong in instruction files. The quote character must differ from the selected delimiter and whitespace.

UTF-8 is recommended; a UTF-8 BOM is accepted. LF, CRLF and CR line endings, and files without a final newline, are accepted. UTF-16/UTF-32 files must be converted first. Binary control characters are rejected.

Matching locations and dates

For local input, each simulation cell uses the nearest file coordinate within max_distance. Distance is straight-line distance in longitude/latitude degrees, not kilometres. Longitude does not wrap at the date line. Equal distances choose the smaller longitude, then the smaller latitude. Each file has its own radius and matching grid; global input needs no spatial match. The legacy searchstep_soil setting does not control this matching; set each file block's max_distance instead.

Static input must have one row per coordinate. Annual input must have one row for every consecutive year. Daily input must have complete consecutive years, with day numbers starting at 1. All coordinates must have the same year range. Rows may be out of order or interleaved between locations; duplicate coordinate/date records are errors. The reader does not fill gaps, interpolate, recycle years or extend values beyond the available year range.

Soil input

Choose exactly one soil description: soildata, soilcode, or the pair soilclay and soilsand. File block names below are literal, case sensitive names. The old file_soildata path and param "file_soil..." settings do not configure this reader. Replace them with named file blocks.

Uniform texture with depth

file "soildata" requires sand, clay, orgc and ph. Sand, clay and organic content are fractions, not percentages. Optional soilc is carbon content in kg C/m² and defaults to zero. Columns silt, cn and bulkdensity may also be supplied and mapped; they are checked as numeric but currently do not feed the soil calculations. In particular, bulk density is not applied to the soil profile. Use mappings for legacy headers such as orgC, pH, CN and soilC. An explicitly mapped optional column must exist.

LPJ soil codes

file "soilcode" has exactly one integer data column, with codes 0–9. Its header may have any name. A headerless coordinate/code file can be used directly:

file "soilcode" (
    path "soils_lpj.dat"
    domain "local"
    timestep "none"
    header "absent"
    max_distance 0.5
)

You can explicitly map column "soilcode" (source "class") when the source column is named class.

Texture varying with depth

Supply both soilclay and soilsand; optionally add soilcoarse and soilph. Each file needs a header whose data columns name contiguous depth intervals in centimetres, starting at the surface:

lon lat 0-20 20-60 60-100
150.75 -33.5 20 30 35

All files must use the same intervals in the same order. Sand, clay and coarse fragments are percentages in these files. pH uses ordinary pH units. Without optional files, coarse fragments default to zero and pH to 6.5. Organic fraction defaults to 0.05 and soil carbon to zero. Use interval names directly; do not add column "clay" or column "sand" mappings.

file "soilclay" (path "clay.txt")
file "soilsand" (path "sand.txt")
file "soilcoarse" (path "coarse.txt")
file "soilph" (path "ph.txt")

Soil depth and slope

Set slope to a nonnegative fixed value in degrees, or to -1 to select file "soilslope", which requires a slope column. A source column named median can be selected with column "slope" (source "median"). Each cell gets its own slope. Values are limited to 0–90 degrees.

With Richards hydrology, positive depth_soil specifies a fixed depth in millimetres. Set depth_soil 0 to use file "soildepth", whose depth column is in metres. Depth maps work with all three soil descriptions. The resulting depth is limited to 0.2–50 m and rounded to 100 mm intervals. Other hydrology schemes use the model's fixed upper plus lower soil depth. Depth and slope files are opened only when the corresponding map is selected.

Diagnosing errors

Files are parsed in full before simulation. Soil initialisation also checks spatial coverage for the requested gridlist. Messages identify the file and, where applicable, physical line, column, coordinate or date. If a file fails:

  1. Set delimiter and header explicitly to resolve detection ambiguities.
  2. Check exact data column names and mappings, and structural header names.
  3. For headerless input, check shape settings and column numbering.
  4. Check missing values, row widths, duplicate records and temporal gaps.
  5. Check coordinates and each file's max_distance; increase it only if using a more distant soil location is appropriate for the simulation.
