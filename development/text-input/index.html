Plain text input

PlainTextInput in framework/textinput.{h,cpp} is a C++17 plaintext input file reader. It reads and validates the entire file during open(), then provides typed values for a selected coordinate and timestep. This is intended as a replacement to TimeDataD.

For instruction-file examples and the complete user option reference, see Plain Text Input Files. For remaining readers and migration decisions, see Plaintext Reader Migration.

Configuration

The instruction file parser accepts named file blocks:

file "soildata" (
    path "soil.dat"
    delimiter "infer"
    header "infer"
    max_distance 0
    column "sand" (source "snd")
    column "silt" (source "slt")
)

Only path is mandatory. Paths may be absolute, or relative to the model's current working directory. A later block with the same name replaces the entire previous block; omitted options return to their defaults.

Option Default Accepted values
delimiter "infer" "infer", ",", ";", "\|", " ", "\t"
sample_rows 64 Nonblank delimiter-sampling rows; 0 uses all rows
header "infer" "infer", "present", "absent"
domain "infer" "infer", "global", "local"
timestep "infer" "infer", "none", "annual", "daily"
calendar "noleap" "noleap", "gregorian"
quote Double quote A single character, or "" to disable
trim_whitespace 1 0, 1
max_distance 0 Euclidean coordinate distance in degrees, 0..360

PLIB does not interpret backslash escapes. The delimiter converter accepts the literal two-character string "\t" as a tab. To specify a double quote explicitly, use quote '"'.

Optional column "name" (source "header") blocks associate a documented model variable with a source data column. For example, the soil component can require sand and silt, while the file uses snd and slt. The model continues to request sand and silt; users do not need to rename the file's headers. Without a mapping, the model name must match a source name exactly.

Domain and timestep expectations

Input data may be global (no coordinates; all gridcells use the same values) or local (with longitude and latitude columns). Additionally, it may be static (one value), annual (one value per year) or daily (one value per day). Data may be any combination of local/global and static/annual/daily.

Instruction files can set TextInputOptions::timestep and domain independently. Both default to Infer. The consuming component may impose further requirements before constructing the reader; soil requires static data and rejects explicit temporal options. With a header, each explicit requirement is validated against the actual columns during open(). For example, Timestep::Daily requires year and day columns, while SpatialDomain::Local requires longitude and latitude columns. SpatialDomain::Global requires their absence. Timestep::None means static.

A component accepting multiple shapes can leave either expectation as Infer and inspect get_timestep() and is_spatial() after opening. It must handle the resulting shape, or reject unsupported shapes during initialisation. Value access still checks the actual shape: daily access to an annual file, for example, throws std::runtime_error. Inference does not resample data.

Row layouts

With a header, reserved structural names determine the format. These are case insensitive: lon/longitude, lat/latitude, year, and day/doy. If either coordinate column is present, both are required. A day column requires a year column. Structural columns can occur in any order. Data column names retain their case and are accessed by exact name; duplicate names, including names differing only in case, are rejected.

For ordinary headerless rows, the component must specify both axes because numeric values cannot reliably identify coordinate/time columns. The source column order is:

Model domain Model timestep Headerless row layout
Global None Data values
Global Annual Year, then data values
Local None Longitude, latitude, then data values
Local Annual Longitude, latitude, year, then data values
Global Daily Year, day-of-year, then data values
Local Daily Longitude, latitude, year, day-of-year, then data values

One headerless row with both axes set to Infer is interpreted as global static data. Otherwise, leaving either axis unspecified without a header is an error. Headerless data columns have names "0", "1", etc., excluding structural columns. With headers, structural columns can occur in any order. For files whose shape the component cannot establish without headers, set domain and timestep in the instruction file, or add structural headers. Headerless data can be mapped using source "0", source "1", etc.; these numbers exclude structural columns.

Headed legacy global static files remain supported:

static A B
0 1.5 2.75

The static column is a validated numeric dummy and is not exposed as data. A headerless global static file treats every field as data; it does not guess whether the first number is a dummy.

Inference and validation

Delimiter inference considers comma, tab, whitespace, semicolon and pipe. It samples up to sample_rows nonblank rows, favouring the most rows with consistent field counts, then the greatest width. Equivalent tab and whitespace parses prefer tab to preserve missing fields. Other equally ranked candidates require an explicit delimiter. The selected delimiter is used to validate every row, including those outside the sample.

The default sample is 64 rows; sample_rows 0 examines all rows. A larger sample can resolve an unrepresentative prefix, but does not make inconsistent field counts valid. Setting the delimiter explicitly avoids inference work. If no candidate produces multiple fields, the reader accepts single-column input using comma as a fallback. This supports global scalar data. Required column declarations still reject files missing expected columns.

Header inference treats an all-text first row as a header. Numeric or boolean first rows remain data. For ambiguous all-text data or numeric column names, set header explicitly.

Column type inference considers every data row. Integers promote to doubles if any value requires it. Boolean text is true/false, case insensitive. Numeric parsing always uses a period (.) as the decimal point, independently of the system locale, and supports decimal exponent notation (1.5e-3). Thousands separators are not supported: neither 1,000,000 nor 1 000 is a number. Commas outside quotes are field separators in CSV, not digit grouping. Partial numbers, hex, non-finite values, overflow and underflow to zero are rejected.

Mixed numeric/text or boolean/text columns fail unless the component declares them as strings. Numeric-looking malformed tokens and missing-value markers (NA, NaN, Inf, Infinity, null) also require an explicit string type. Unquoted empty fields fail. Quoted empty strings are valid text but fail in numeric and boolean columns. These rules deliberately favour detecting bad simulation input over silently converting it to a different type.

Quoted fields can contain delimiters and doubled quote escapes. Quoted whitespace is preserved. Unterminated quotes, text following a closing quote, quotes in unquoted fields, and multiline fields are rejected. Whitespace separation collapses spaces and tabs; the other delimiters preserve empty fields. LF, CRLF, CR, a final row without a newline, a UTF-8 BOM, and blank lines are accepted. Binary control characters, including NUL, are rejected.

Input uses ASCII-compatible bytes; strings are preserved without transcoding or UTF-8 validation. UTF-8 is recommended, and its BOM is stripped. Other ASCII-compatible encodings can carry text unchanged, but the caller must know how to interpret those bytes. UTF-16 and UTF-32 BOMs cause an immediate error asking the user to convert to UTF-8; their encodings are not supported. Without a BOM, such input normally fails the NUL/control-character checks.

Longitude must be finite and in -180..180, and latitude in -90..90. When the model requests data for a particular gridcell, data for the nearest gridcell within the specified distance will be used. A search radius of zero requires an exact match; equal-distance ties choose the lexicographically smaller coordinate. There is no longitude wrapping. coordinates() returns the matched file coordinate, not the query.

Rows may be unordered or interleaved among cells. Static coordinates and coordinate/time pairs must be unique. Annual years must be consecutive. Daily years must be complete and consecutive, with days numbered from 1; noleap has 365 days, and gregorian applies the Gregorian leap-year rule. Every cell must have the same year range. There is no interpolation or clamping outside the available years. Diagnostics identify the input path, physical line number and relevant column/value or coordinate/time conflict.

Using the API

#include "parameters.h"
#include "textinput.h"

auto soil_options = text_input_options("soildata");
soil_options.timestep = Timestep::None;
soil_options.domain = SpatialDomain::Local;
soil_options.required_columns = {{"sand", ColumnType::Double},
                                 {"silt", ColumnType::Double}};
PlainTextInput soil(soil_options);
soil.open();
soil.load(lon, lat);
double sand = soil.get<double>("sand");

auto forcing_options = text_input_options("forcing");
forcing_options.timestep = Timestep::Daily;
forcing_options.domain = SpatialDomain::Infer; // Global and local supported.
forcing_options.required_columns["value"] = ColumnType::Double;
PlainTextInput forcing(forcing_options);
forcing.open();
forcing.validate_years(first_simulation_year, last_simulation_year);
forcing.validate_gridcells(required_gridcells); // (longitude, latitude) pairs
forcing.load(lon, lat);
double value = forcing.get_day<double>("value", year, day_of_year); // 1-based
// get_auto() accepts the model's 0-based day, unlike get_day().
double current = forcing.get_auto<double>("value", date.get_calendar_year(), date.day);

Call open() and coverage/type checks during model initialisation, before starting a simulation. validate_years() checks every cell because the reader has already validated identical coverage. A file alone cannot know the simulation's requested years, required columns or required gridlist. Pass the complete requested gridlist to validate_gridcells() at startup. It uses the same nearest-cell/radius rules as load(), accepts global data for every valid coordinate, and preserves any current selection. is_spatial() and get_timestep() remain available for inspecting the inferred structure.

get<double>() accepts both integer and double columns. Other type conversions require an explicit column type. load() may be called repeatedly; failed selection clears the previous selection. Failed open() leaves the reader unopened and can be retried after fixing the file.

The reader owns all parsed columns and records in memory. During open() it also owns the raw file buffer and physical line index. Borrowed field ranges never outlive that buffer; the raw text is released after validation. Two passes infer types and fill reserved typed columns, without stream construction per number. The initial implementation is entirely in-memory; memory mapping, selective gridlist storage and multithreaded parsing are on the TODO list.

The private Impl class keeps column storage, indexes, tokenisation helpers and their dependencies out of the public header.

The reproducible million-row benchmark, fixture generator, JSON reporting and baseline comparison live in performance/; see performance/README.md in the repository for build and run commands.
